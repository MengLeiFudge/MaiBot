# QQBot 私聊主动续聊

`qqbot_proactive` 为独立机器人提供私聊空闲续聊。把 `config.example.toml` 复制为本机 `config.toml`，将 `[plugin].enabled` 设为 `true`，并确认 `[proactive].bot_qq` 对应本实例。主人账号只从 `qqbot_identity` 的本机 `[identity].owner_qq` 读取，示例不保存真实主人 QQ。

插件每 15 秒查询一次已有主人私聊。最近一条消息必须由当前机器人发送；尚未回答的主人消息不会触发主动续聊。每次观察到新消息后，随机等待 `min_idle_seconds` 到 `max_idle_seconds` 再尝试，默认 180–300 秒。新消息会重新计时；主人回复还会重置无人回应额度。

到期后，插件通过 `maisaka.proactive.trigger` 请求一轮自然续聊，由原生 Planner 和 Replyer 决定是否发言与如何表达。任务会提醒模型尊重道别、休息和忙碌，不重复催促；这属于模型判断，不是固定时段的硬性静默开关。插件不处理群聊，不创建陌生人会话，也不直接发送固定消息。

`max_unanswered_turns` 默认 2，限制主人没有新回复时提交主动任务的次数，不是保证发送的消息数。一次任务可能保持安静，也可能由原生回复拆分器拆成多条。额度和下次检查时间原子保存到插件标准 `data_dir/schedule.json`，不保存聊天正文。提交前先保留额度；RPC 失败或超时也消耗一次，以免请求实际已入队却重复提交。重启及配置重载保留额度；损坏的状态会报告错误并阻止调度，不自动清空。

依赖 `qqbot_identity`。能力仅为读取当前实例及身份配置、查询现有私聊和消息、触发原生主动任务。插件没有独立模型调用、发送消息或数据库写入能力。卸载或本插件配置更新会取消后台任务，已在框架中入队的任务仍由框架处理。
