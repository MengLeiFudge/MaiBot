# QQBot 自身状态与主动续聊

`qqbot_proactive` 为独立机器人维护跨会话自身状态，并提供话题延续和日常关心。把 `config.example.toml` 复制为本机 `config.toml`，将 `[plugin].enabled` 设为 `true`，并确认 `[proactive].bot_qq` 对应本实例。主人账号只从 `qqbot_identity` 的本机 `[identity].owner_qq` 读取。主动联系仅处理这个账号的已有 QQ 私聊；自身活动与休息状态覆盖本实例的全部私聊和群聊。

## 跨会话自身状态

Planner 和 Replyer 在每次请求前读取同一份自身状态。`set_self_state` 工具通过 `tool_search` 获取，参数为 `mode`（`active` / `resting`）、`activity`（最多 240 字）、当前 `revision` 和 `duration_seconds`。摘要只能写可公开的自身活动或心情，不得放入他人隐私、聊天原文、账号或提示指令。各会话长期记忆的检索边界保持独立。

决定自己睡觉或休息时，先保存 `resting` 和 1–86400 秒的有效期，再简短告别并结束。间隔由模型根据对话决定。其他会话立即停止 QQ 发言，发起会话仅保留最多两分钟的告别窗口，以容纳模型生成和拆分发送。期间的重复休息更新不会延长告别窗口。自身状态、告别截止和版本均跨重启保留。

休息期间主动续聊检查暂停；`send_service.before_send` 拦截其余 QQ 文本、图片、表情等发送，包括尚未通过发送 Hook 的旧回复；已经交给底层发送的消息无法撤回。Planner 仍可能被入站消息触发，提示要求保持安静，不轮询和反复发送。只有状态工具成功执行后才存在确定的发送约束；模型仍负责理解对话、选择状态和更新时机。插件不通过关键词扫描把每句“睡了”直接当作休息指令。

普通新消息和 @ 不会在程序中清除休息。模型收到明确唤醒请求并决定醒来时先更新为 `active`，否则等有效期到达；下一次状态读取会自动恢复为可交流。主动状态的有效期可以为零表示持续。工具用版本核对拒绝其他会话的过时更新，调用方需要结合返回的最新状态重新决定。别人说“我睡了”只影响对那个人的联系计划，不表示机器人休息。

## 联系节奏

插件每 15 秒检查消息。新消息后随机空闲 180–300 秒再考虑续聊，范围由 `min_idle_seconds`、`max_idle_seconds` 控制。尚未回答的主人消息优先交给正常聊天链路；十分钟仍无回复时允许重新判断是否有回应价值，不会因此永久停止主动联系。

`max_unanswered_turns` 默认 2：无人回应时实际发出两轮后，之后每轮间隔至少随机 2–3 小时，由 `min_retry_seconds`、`max_retry_seconds` 控制。收到主人新消息后恢复短间隔。模型决定等待时可自行选择 5 分钟至 24 小时后的下一次检查，无人回应两轮后的长间隔下限仍有效。请求失败或入队后没有观察到实际发言不消耗轮数，按长间隔退避。

计数依据是主动任务预留时间之后、没有主人新消息时观察到的机器人消息。框架在发送成功后才将消息写入记录；同次回复拆分出的多条只计一轮。公开消息接口没有主动任务 ID，因此同一空闲窗口内其他来源的机器人消息也可能计入一轮，不能严格归因到某个主动任务。

## 话题与表达

仅在空闲到期时，通过公开 `llm.generate` 调用现有 `planner` 模型一次，推理与 JSON 正文共享 8192 token 上限，模型等待上限 60 秒，整轮检查上限 90 秒。读取最近 24 条私聊文本（每条最多 800 字）和已有话题，判断是否适合联系。最新主人消息若不在这 24 条内则额外补入。普通回复不经过这一步。最多保留三个待跟进话题，每个必须引用真实主人消息或已有话题的来源 ID；来源七天后过期。模型负责移除已经完成、否定或不愿继续的话题，也负责判断关心时机，内容理解仍可能有误。

明确要求不要打扰或停止主动联系时，持久保存静默状态，直到主人再次说话。临时忙碌、睡觉或道别按上下文安排有限等待，到期重新考虑；单纯未回复不等于拒绝。没有适合的新内容时允许不发，不为了凑数生成固定问候。模型判断结束后重新核对身份、最新消息和计划，期间有新交流或计划变化就丢弃过时决定。

最终通过 `maisaka.proactive.trigger` 交给原生 Planner/Replyer 表达。插件提供话题方向，保留现有人设、称呼、语气、消息拆分及打字延时；不直接发送固定文案。已在框架入队的任务仍由框架执行，插件提示其以新消息为先，无法撤销已入队任务。

## 自己安排后续联系

Planner 可以通过 `tool_search` 查找 `schedule_private_followup`：`schedule` 安排 300–86400 秒后重新考虑联系，`cancel` 取消当前计划。安排必须引用同私聊七天内的真实主人消息 ID，并给出不超过 400 字的联系方向。一个私聊保留一个计划，新计划覆盖旧计划，跨重启保留；无法取得来源或身份不符时不创建。

普通规划 Hook 只提供工具说明，不额外调用模型。到期由后台模型结合最新对话判断，允许继续等待或放弃，随后消费这次计划；已完成的事情不要求机械执行。新消息会恢复短间隔额度并在到期判断时纳入上下文；已有指定时间优先于普通空闲间隔。临时忙碌通常适合安排稍后关心，明确不要打扰时保持静默。

这是一套聊天联系计划，不是保证准点送达的提醒服务。程序需要运行；检查有 15 秒粒度，另有模型、原生队列和打字耗时。无人回应两轮后，计划也遵守长间隔下限。公开 API 不能撤销已在框架入队的主动任务。

## 工作区日程与作息

`quiet_start_hour`、`quiet_end_hour` 是本机时区的主动联系静默窗口，支持跨午夜；两者相同表示关闭。蓝铃部署使用 00:00–08:00。窗口内暂停普通空闲续聊和到期联系计划，恢复后结合最新消息重新判断，正常入站回复仍走原生链路。只有 `set_self_state` 保存的休息才会统一拦截群聊和私聊，不能把静默窗口当成已经入睡。

`day_plan_file` 指定个人工作区日程文件，蓝铃可用原有文件工具编辑，例如：

```json
{"date":"2026-11-11","entries":[{"time":"16:00","intent":"查找滑板入门教程并整理学习笔记"}]}
```

日期必须是 `YYYY-MM-DD`，时间为不重复的 `HH:MM`；最多十二项，每项意图 1–160 字，文件上限 16 KiB。后台每 15 秒读取一次，缺失、无效、删除或日期过期时不使用旧计划。只把当天最近一项和后面两项提供给主人私聊的 Planner 与已有主动联系判断，不向群聊注入私人计划，不新增日程生成模型调用。

日程只是意图，不是已执行事实，不自动运行文件、搜索视频或修改自身状态。模型需要实际调用已有能力才能完成活动；休息继续使用统一状态工具。可以在交流中自然安排，也可以先回读工作区日记再决定。此处吸收麦麦恋人的时段安排和当前日程提示；原恋人插件与私聊转发工具不参与蓝铃运行，不保留第二套好感度、身份、记忆或主动调度。

## 本机状态

发言轮数、下次检查时间、待发标记、静默状态、话题摘要和单次联系计划原子写入插件标准 `data_dir/schedule.json`。独立的 `data_dir/self_state.json` 保存机器人自身活动、休息期限、告别窗口和版本，所有会话共用这一份文件。先写盘成功再发布新状态，写入失败不会返回成功。摘要和计划只保存在本机，不进 Git；日志只记录动作、数量、版本和间隔，不记录正文或身份账号。调度查询最多回看 30 天的已有消息，话题独立按七天过期。

调用模型及入队前先持久化失败退避时间，得到有效决定后才更新下次检查。重启和配置重载不刷新次数，也不提前既有截止时间；旧状态缺少联系计划时按无计划读取。旧版 `attempts` 记录的是入队次数，升级时不当作实际发言；已有旧尝试时至少保留两小时休息。损坏状态会报错并停止加载，不自动清空。配置兼容原 `0.1.0` 格式。

依赖 `qqbot_identity`，使用公开配置、私聊、消息、LLM 与主动任务能力。卸载或本插件配置更新会取消后台任务。源码只部署于蓝铃，不参与棉花糖家族插件同步。
