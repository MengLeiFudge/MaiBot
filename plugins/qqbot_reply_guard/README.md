# 原生回复规则

`qqbot_reply_guard` 为已有原生回复资格的群聊和私聊追加阶段答复与研究规则。公开答复统一使用原生 `reply`：Planner 决定回应内容，Replyer 结合完整人设、说话风格、表达习惯和聊天上下文生成正文，再经过原有后处理分段和发送管线。插件只追加上下文，保留全部原生工具、附件参数及后续研究循环。

复杂问题已有可靠且有用的阶段结论时，可以先调用 `reply`，在 `reply_reference` 中说明已确认事实和本次仅需回应的部分，随后继续查询或研究，有新增证据后再补充。依赖工具结果的结论须等待实际结果；普通聊天正常回答，不机械报进度，不重复已有内容，内部分析保持隐藏。查询失败时区分已有结论和缺失证据，只有新线索、不同核验方法或可恢复的临时错误才继续尝试。

复制示例为本机 `config.toml`，启用 `plugin.enabled`，确认 `guard.bot_qq` 是本实例账号。保留身份插件及知识插件提供的真实身份与检索证据。原生发送流程负责消息历史、记忆写回和已有发送 Hook。配合 [qqbot_reply_timing](../qqbot_reply_timing/README.md)，首条只按后处理后的第一段计算等待，抵扣本轮已耗时；后续分段及研究补充按原速度发送。

本插件只使用公开 `maisaka.planner.before_request` Hook 和 `config.get`，不注册消息发送工具，不保存聊天正文或发送回执。质量与耗时维护要求见根 `docs/model-routing.md` 的“回复耗时排查”。
