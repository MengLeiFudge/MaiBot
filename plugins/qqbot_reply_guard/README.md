# 私聊公开答复与执行检查

`qqbot_reply_guard` 为已核验的主人私聊提供 `send_reply`：直接发送模型已经写好的公开答复，发送后原生工具循环继续运行。需要原生回复器组织表达、生成长文或发送附件时仍可使用 `reply`。插件同时处理规划器明确准备回应、却没有调用 `reply` 的漏执行。复制 `config.example.toml` 为本机 `config.toml`，启用 `[plugin].enabled`，确认 `[guard].bot_qq` 对应当前实例。主人账号读取 `qqbot_identity` 本机配置。

`send_reply` 的 `msg_id` 绑定当前最新主人消息，`text` 为 1–2000 字的公开正文，默认 `phase=answer`。复杂问题已有可靠且有用的部分结论时，可先以 `phase=progress` 发出，再查询、研究并补充结果。简单聊天直接回答；阶段消息有新信息才发送，不机械报进度，不转发内部分析。工具本身不会结束原生规划循环，也不在后台另开研究任务。同一批同时选择同目标的直接最终答复和原生 `reply` 时，保留直接答复并移除未携带附件的原生重述；阶段答复、研究工具和带图片、表情或提及的原生调用保留。查询失败时区分已有结论和缺失证据，只有新线索、不同核验方法或可恢复的临时错误才继续尝试，不能把查证失败说成成功。

直接答复走公开 `send.text` 能力，关闭模拟打字和引用，成功后由原生发送管线保存消息、同步 Maisaka 历史并触发原有记忆写回；共享休息状态等发送 Hook 仍然生效。发送前重新核对主人、会话和最近主人消息。已回复后的补充继续使用同一个来源 ID；收到新主人消息、配置重载或卸载后，旧目标不可再发送。同文并发调用共享回执；失败、超时和取消不自动重发。其他会话的规划请求移除该工具，直接调用也会被拒绝。

优化优先比较首次有用答复和完整完成时间，同时核对事实、引用、上下文和原有人设。保持模型、最高思考强度、记忆、检索及必要研究，不用降低质量或缩短必要推理换取首条消息；token 成本不作为这项优化的限制。真实模型对照必须明确区分隔离回放与 QQ 端到端耗时。

原生漏执行核对只处理主人的已有 QQ 私聊，且最近消息必须仍由主人发送、已出现在本轮规划上下文中。同一条新主人消息第一次进入规划时等待 2 秒，给连发补充留出时间；期间有新消息时交给原生中断流程重新收集上下文。后续围绕同一消息调用工具不重复等待。规划提示要求把连续消息作为一轮理解，由模型决定回应、等待或保持安静，避免逐条回答。规划后已有函数调用或平台原生活动时，保持原输出。只有纯文本规划、目标尚未回复时，才用现有 `planner` 模型对这份规划核对一次动作，最长等待 15 秒。明确需要回应时补上单个原生 `reply` 调用，沿用原生回复器、人设、发送拆分和延时，引用关闭。

核对不重新策划话题。规划决定保持安静或核对不能确定意图时保持原结果。同一消息在插件进程内只核对一次，失败或超时记录日志，不循环重试。核对前后都重新确认最近消息，发现新消息或机器人已经回复时丢弃旧动作；群聊和机器人已回复后的主动续聊不受影响。

原生回复工具仍可能调用失败或生成失败，本插件不重发已有工具调用。动作核对仍依赖模型理解，不能保证所有无工具输出都能修复。使用 `send_reply` 不再额外请求回复模型；使用原生 `reply` 时保留回复器调用。只有触发漏执行核对时，才增加一次规划模型调用及其耗时。核对调用的 token 使用由框架按本插件请求记录，原始 Planner 的 token 统计保持原值。

在本机 `bot_config.toml` 的 `[chat.reply_timing]` 中设置 `planner_interrupt_max_consecutive_count = 10`，允许新消息打断正在运行的 Planner，并在原生静默窗口结束后重新收集消息。`0` 表示禁用打断。连续打断达到上限后该次请求正常完成。此配置不取消已经进入 Replyer 或发送阶段的任务，也不能撤回已经发送的消息。

Planner 和待回复私聊的 Replyer 都追加联网工具说明：`tool_search` 查找本地延迟加载工具，规划器再调用 [qqbot_web_search](../qqbot_web_search/README.md) 提供的 `web_search` 取得官网检索证据。回复依据实际结果和来源链接，未查询时不声称已联网。执行检查插件本身不提供搜索服务、不强制每轮联网。

本轮主人消息含普通引用时，通过 `message.get_by_id` 读取同会话的原文，最多展开三个引用、每条 2000 字，不递归、不请求二进制媒体。原文、发送者角色、原消息时间及截断状态作为历史资料分别进入 Planner 和 Replyer，避免只看到 ID 后误用合并转发工具。没有取得原文则明确标记缺失。记忆规则区分检索被过滤、失败和无结果，要求不凭空补写共同经历；最终表达仍取决于模型。

使用公开 `maisaka.planner.before_request` / `after_response`、`maisaka.replyer.before_request` Hook、Context Item schema 1，以及配置、聊天流、消息查询、`send.text` 和 `llm.generate_with_tools` 能力。不修改用户配置中的人设，不持久化额外聊天副本，不注册后台调度。本插件日志只记录核对状态、发送阶段、字数和错误类型，不输出内部推理或公开正文。

回归验证：在项目目录使用本机 Python 执行 `-m unittest discover -s pytests -p test_qqbot_public_replies.py -v`，验证 SDK 能力出口、阶段续答、并发去重、新消息、身份变化及取消；该测试截获消息出口，不连接 QQ 或模型。真实模型回放仍需取得当前任务的测试授权。
