# QQBot 连发、引用与短回复

`qqbot_reply_guard` 为夜凛主人私聊从接收时起收集两秒内的连续消息，并为 Planner 和原生 Replyer 展开本轮同会话的普通引用原文。准备上下文已经花掉的时间计入两秒窗口，新消息仍交给原有中断流程重新收集。

插件不再追加回复决策、搜索和记忆规则，也不在生成后调用另一个模型核对执行动作。阶段回复与历史查阅指导放在原生 `[chat.reply_style]` 配置中；联网能力由现有搜索插件提供。Planner 决策后调用原生 `reply`，原生 Replyer 结合完整人设、上下文和工具证据生成正文，再经过原有后处理分段与发送。

夜凛群聊和私聊的短回复通过公开 `maisaka.reply.before_post_process` Hook 关闭本次随机拆分：正文去除首尾空白后不超过 `response_splitter.max_length` 时，完整保留句子、标点和段内换行；长回复沿用原生分段。只调整 `enable_splitter`，原生文本清理、错别字、附件和发送选项保持。插件关闭、目标账号不匹配、空回复或调用方已跳过后处理/禁用分段时不修改本次策略。

维护断句时以表达完整、停顿自然为准，不以增加聊天气泡数量为目标。变更后运行 `pytests/test_qqbot_short_reply.py`，确认原生回复、后处理及发送出口中的正文与标点一致，并保留长回复、附件、失败处理和打断行为。

`qqbot_reply_timing` 继续负责按分段后的第一段抵扣本轮已耗时，以及首条公开消息成功前的新消息打断。后续分段和研究补充保持原速度。

将 `config.example.toml` 复制为本机 `config.toml` 后启用。连发与引用功能核对目标机器人 QQ、身份插件配置中的主人和真实私聊，不向群聊或其他私聊追加引用资料；短回复策略适用于目标账号的正常回复。插件不调用模型或发送接口。
