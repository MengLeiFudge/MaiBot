# QQBot 视频与历史阅读

普通图片和表情由 MaiBot 原生多模态接收、保存并交给主模型；本插件不再设置入站图片门控，也不另建普通图片补图链。Planner 和 Replyer 均使用 `[visual]` 的 `multimodal` 模式，所选模型须实际支持视觉。表情收集沿用原生配置。所有消息处理遵守根工作区的 [消息完整性与按需触发](../../../docs/message-context.md)。

插件保留框架没有提供的三项能力：

- QQ 视频、HTTP/HTTPS 链接中的视频和合并转发中的视频，统一识别并将实际分镜附给 Planner 和 Replyer，见 [视频分镜](VIDEO.md)。
- 主人私聊中的 B站搜索、选定视频阅读与本机长视频先概览后精读。工具分别为 `bilibili_search`、`bilibili_watch`、`watch_local_video`；本机长视频默认先取全片时间轴原图和已有字幕，再按用户问题选片段精读。通过原生 `tool_search` 发现工具；执行时核对身份插件中的主人与真实私聊。群聊和其他私聊不能读取本机路径。
- 按需读取当前会话更早的原消息和实际图片，使用 `read_chat_history`。默认每页30条，`count` 可取1–100；使用返回的 `next_before_message_id` 继续向前翻页，不受近期聊天窗口条数限制。不会每轮自动补读历史，也不注入额外的历史提示 Hook。

历史工具保留说话者、时间、引用和来源树，原图作为原生工具 `content_items` 返回。同一时间的记录也能连续翻页。旧记录缺少原图时，仅通过公开 NapCat API 读取并核对原消息，再使用协议返回的图片文件标识恢复；不把聊天中的路径当作图片来源。单张图片失败保留其他消息和附件，并明确标记未读取。

将 `config.example.toml` 复制为本机 `config.toml` 后启用。本人 QQ 通过公开配置热重载；主人账号只使用身份插件本机配置。视频工具的依赖、限时与读取范围见 VIDEO.md，搜索摘要和文件元数据都不构成已经观看的证据。
