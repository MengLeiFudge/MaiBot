# 视频分镜

在聊天中发送可公开访问的视频链接，或 QQ 视频附件及含视频的合并转发。插件使用 [DSH Video Storyboard](https://github.com/SAOS-3624/dsh-video-storyboard) 扫描画面变化，检测镜头边界，再按切换密度排版代表帧。Planner 和 Replyer 的公开请求 Hook 直接把分镜原图、逐格时间清单及可用字幕附到原消息的 Context Item。群聊、私聊共用视频能力，聊天触发和表情收集沿用原生配置；普通图片不经过插件门控。

支持 B站长链、b23 短链、YouTube、X/Twitter、抖音、小红书、微博、腾讯视频、西瓜等域名，以及 HTTP/HTTPS 视频文件直链。网页解析由 yt-dlp 提供；登录限制或站点风控可能阻止下载。QQ 视频地址由本地 `napcat_adapter` 的 `_build_video_text_segment` 保留；缺少地址时提示改发链接或重传。

## 安装与配置

使用本项目虚拟环境安装清单中的依赖，并安装 Node.js 20 或更新版本。FFmpeg 和 ffprobe 来自 `ffmpeg-binaries`，也可放在本插件的 `tools/ffmpeg/bin/` 或 PATH 中。分镜引擎源码随插件提供，无需安装 DSH 应用。B站下载使用直连；X/Twitter和其他站点复用本机 HTTP/HTTPS 代理。X/Twitter使用公开帖子的嵌入信息解析视频，该接口可能不提供帖子的全部媒体或元数据。网页下载通过 curl_cffi 提供浏览器 TLS，并保持证书校验。

插件顶层的 `video_enabled` 默认开启，在 `config.toml` 的 `[plugin]` 前设置：

```toml
video_enabled = true

[plugin]
enabled = true
config_version = "0.2.0"
```

Planner 和 Replyer 使用的主聊天模型须开启且实际支持 `visual`。既有 `[visual]` 的 `text` 模式不影响请求 Hook 补入的图片。视频不额外调用 `vlm` 生成摘要。

## B站搜索与阅读

蓝铃的主人私聊可以通过 `tool_search` 找到两个本地工具：
- `bilibili_search`：调用 B站公开搜索接口，返回清理过的标题、作者、时长、简介、BV号和页面 URL；结果只是候选资料。
- `bilibili_watch`：接收候选 URL 或 BV号，复用本插件的 yt-dlp 下载、字幕/OCR 和 DSH Video Storyboard 分镜链，把最多4张真实 PNG 分镜作为工具媒体交给主模型。
工具只允许蓝铃已绑定的主人私聊，执行时还会核对身份插件和真实会话；群聊、其他私聊或无法核验身份时拒绝。搜索接口与现有B站下载一样不使用本机代理。只有 `bilibili_watch` 成功返回分镜图时才可描述视频画面；标题、简介或下载失败文本不构成观看证据。

## 本机视频

主人私聊明确给出 Windows 绝对路径并要求观看时，通过 `tool_search` 发现 `watch_local_video`，传入 `path`、可选 `start_seconds` 和 `end_seconds`。例如 `D:\Videos\example.mp4` 默认读取0–600秒；用结果中的 `next_start_seconds` 继续下一段，也可以按用户关心的位置读取。大文件直接在本机解码，不上传、复制或先把整部转码。

每次工具返回真实 PNG 分镜、总时长、实际读取范围和继续位置；OCR及清单使用原视频绝对时间。只有取得实际分镜才可讨论画面，片段与离散抽样不能说成整片已经看完。可以先公开有用且已确认的内容，再继续阅读。工具仅对真实主人私聊开放，群聊、其他私聊和 UNC 网络路径均拒绝；身份配置沿用现有插件，不另设主人名单。

## 处理边界

- 每条消息最多处理一个视频，每台机器人同时处理一个任务。入站只登记来源，下载延后到实际模型请求。QQ 本机视频及转发视频通过公开 NapCat API 读取原消息，在核对消息 ID、会话、群 ID 和原发送者后，使用结构化视频段返回的下载地址或绝对文件路径，路径不可读时按原视频文件标识调用 `get_file` 补下载；自动附件入口不从聊天正文读取磁盘文件；主人私聊明确指定的本机路径由下述工具单独核验。转发最多3层、64节点、4次查询和256个消息段，依赖 `api.call` 权限。
- 公网下载仍限制80 MiB、10分钟，网页视频选择不超过720像素的可用档位并合并音轨。本机文件直接读取，不复制整部、不套下载大小上限，每次读取最多10分钟，可按返回位置继续；解码分辨率上限4000万像素。
- 使用 DSH `compact` 策略，最多4张图。分镜数量随画面变化决定，图片预算可能合并镜头；离散采样不能保证呈现所有瞬间。
- 总处理预算180秒，网页下载90秒，字幕取帧30秒、OCR子进程65秒，分镜子进程110秒；总预算先到时会结束整个进程树。
- 优先使用下载到的中英文站点字幕，其次使用容器内嵌字幕。没有字幕文件或字幕轨时，用 Windows 自带中文 OCR 每0.5秒读取视频画面，合并连续重复行，单独附上时间表；不用缩小后的分镜格子读取歌词。需要本机安装中文 OCR 语言资源。结果标注采样范围和实际完成状态，可能包含歌词、片名、水印及识别错字；不等于完整音频转写。
- 分镜原图最多缓存8项、24 MiB、1小时，仅存进程内存。消息映射最多128项，并按真实会话和消息ID隔离。QQ原文件取得失败后，同一原消息120秒内复用失败结果，避免规划、回复和后续请求重复发起未完成的QQ下载；新发送的视频消息可立即重试。每次请求优先附上最新视频；后续引用时间清单回答追问。
- OCR最多1200帧、55秒识别预算，文字时间表最多32000字符；达到限制时明确标记未完成。临时视频、字幕、采样帧和引擎状态在成功、失败或取消后清理，QQ原有视频缓存保持原样。卸载等待任务和子进程结束。

网页下载遇到临时连接中断时，在既有90秒预算内最多尝试三次。当前请求已附入成功分镜及对应图片时，以本次读取结果为准，先前规划或聊天中的失败状态已过期。

下载或分镜失败时，主模型收到带实际原因的 `[视频未读取]`，不应根据标题或其他图片编造内容。日志记录附给模型的图片数、格数、时长和工具错误；下载 URL 在工具诊断中脱敏。来源和许可证见 [vendor/NOTICE.md](vendor/NOTICE.md)。
