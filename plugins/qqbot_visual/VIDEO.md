# 视频分镜

在聊天中发送可公开访问的视频链接，或 QQ 视频附件及含视频的合并转发。插件使用 [DSH Video Storyboard](https://github.com/SAOS-3624/dsh-video-storyboard) 扫描画面变化，检测镜头边界，再按切换密度排版代表帧。Planner 和 Replyer 的公开请求 Hook 直接把分镜原图、逐格时间清单及可用字幕附到原消息的 Context Item。群聊、私聊共用视频能力，聊天触发、图片门控和表情收集沿用原配置。

支持 B站长链、b23 短链、YouTube、X/Twitter、抖音、小红书、微博、腾讯视频、西瓜等域名，以及 HTTP/HTTPS 视频文件直链。网页解析由 yt-dlp 提供；登录限制或站点风控可能阻止下载。QQ 视频地址由本地 `napcat_adapter` 的 `_build_video_text_segment` 保留；缺少地址时提示改发链接或重传。

## 安装与配置

使用本项目虚拟环境安装清单中的依赖，并安装 Node.js 20 或更新版本。FFmpeg 和 ffprobe 来自 `ffmpeg-binaries`，也可放在本插件的 `tools/ffmpeg/bin/` 或 PATH 中。分镜引擎源码随插件提供，无需安装 DSH 应用。B站下载使用直连；X/Twitter和其他站点复用本机 HTTP/HTTPS 代理。X/Twitter使用公开帖子的嵌入信息解析视频，该接口可能不提供帖子的全部媒体或元数据。网页下载通过 curl_cffi 提供浏览器 TLS，并保持证书校验。

插件顶层的 `video_enabled` 默认开启，在 `config.toml` 的 `[plugin]` 前设置：

```toml
video_enabled = true

[plugin]
enabled = true
config_version = "0.1.0"
```

Planner 和 Replyer 使用的主聊天模型须开启且实际支持 `visual`。既有 `[visual]` 的 `text` 模式不影响请求 Hook 补入的图片。视频不额外调用 `vlm` 生成摘要。

## 处理边界

- 每条消息最多处理一个视频，每台机器人同时处理一个任务。入站只登记来源，下载延后到实际模型请求。QQ 本机视频及转发视频通过公开 NapCat API 读取原消息，在核对消息 ID、会话、群 ID 和原发送者后，使用结构化视频段返回的下载地址或绝对文件路径，路径不可读时按原视频文件标识调用 `get_file` 补下载；不从聊天正文读取磁盘文件。转发最多3层、64节点、4次查询和256个消息段，依赖 `api.call` 权限。
- 视频不超过80 MiB、10分钟、4000万像素；网页视频选择不超过720像素的可用档位，并合并可用音轨。
- 使用 DSH `compact` 策略，最多4张图。分镜数量随画面变化决定，图片预算可能合并镜头；离散采样不能保证呈现所有瞬间。
- 总处理预算180秒，网页下载90秒，字幕取帧30秒、OCR子进程65秒，分镜子进程110秒；总预算先到时会结束整个进程树。
- 优先使用下载到的中英文站点字幕，其次使用容器内嵌字幕。没有字幕文件或字幕轨时，用 Windows 自带中文 OCR 每0.5秒读取视频画面，合并连续重复行，单独附上时间表；不用缩小后的分镜格子读取歌词。需要本机安装中文 OCR 语言资源。结果标注采样范围和实际完成状态，可能包含歌词、片名、水印及识别错字；不等于完整音频转写。
- 分镜原图最多缓存8项、24 MiB、1小时，仅存进程内存。消息映射最多128项，并按真实会话和消息ID隔离。QQ原文件取得失败后，同一原消息120秒内复用失败结果，避免规划、回复和后续请求重复发起未完成的QQ下载；新发送的视频消息可立即重试。每次请求优先附上最新视频；后续引用时间清单回答追问。
- OCR最多1200帧、55秒识别预算，文字时间表最多32000字符；达到限制时明确标记未完成。临时视频、字幕、采样帧和引擎状态在成功、失败或取消后清理，QQ原有视频缓存保持原样。卸载等待任务和子进程结束。

下载或分镜失败时，主模型收到带实际原因的 `[视频未读取]`，不应根据标题或其他图片编造内容。日志记录附给模型的图片数、格数、时长和工具错误；下载 URL 在工具诊断中脱敏。来源和许可证见 [vendor/NOTICE.md](vendor/NOTICE.md)。
