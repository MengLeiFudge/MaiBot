# 视频分镜

在聊天中发送可公开访问的视频链接，或 QQ 视频附件及含视频的合并转发。插件使用 [DSH Video Storyboard](https://github.com/SAOS-3624/dsh-video-storyboard) 扫描画面变化，检测镜头边界，再按切换密度排版代表帧。Planner 和 Replyer 的公开请求 Hook 直接把分镜原图、逐格时间清单及可用字幕附到原消息的 Context Item。群聊、私聊共用视频能力，聊天触发和表情收集沿用原生配置；普通图片不经过插件门控。

HTTP/HTTPS 链接统一交给 yt-dlp 识别，已有站点提取器与通用网页提取器共同处理；新域名直接进入相同流程。通用提取器尝试网页声明的视频元数据、HTML5 播放器、受支持的嵌入播放器，以及 MP4、HLS、DASH 等媒体地址。是否能够读取取决于页面实际提供的媒体和访问条件，登录、验证码、加密播放或解析能力限制可能阻止下载。QQ 视频地址由本地 `napcat_adapter` 的 `_build_video_text_segment` 保留；缺少地址时通过协议端读取原视频段。

## 安装与配置

使用本项目虚拟环境安装清单中的依赖，并安装 Node.js 20 或更新版本。FFmpeg 和 ffprobe 来自 `ffmpeg-binaries`，也可放在本插件的 `tools/ffmpeg/bin/` 或 PATH 中。分镜引擎源码随插件提供，无需安装 DSH 应用。网页与播放器解析由依赖中的 yt-dlp 维护；插件负责收集链接、下载预算、分镜和消息归属。B站下载使用直连，其他网页复用本机 HTTP/HTTPS 代理。X/Twitter提取器使用公开帖子的嵌入信息，该接口可能不提供帖子的全部媒体或元数据。网页下载通过 curl_cffi 提供浏览器 TLS，并保持证书校验。

插件顶层的 `video_enabled` 默认开启，在 `config.toml` 的 `[plugin]` 前设置：

```toml
video_enabled = true

[plugin]
enabled = true
config_version = "0.2.0"
```

Planner 和 Replyer 使用的主聊天模型须开启且实际支持 `visual`。既有 `[visual]` 的 `text` 模式不影响请求 Hook 补入的图片。视频不额外调用 `vlm` 生成摘要。

## B站搜索与阅读

蓝铃的主人私聊可以通过 `tool_search` 找到两个本地工具：
- `bilibili_search`：调用 B站公开搜索接口，返回清理过的标题、作者、时长、简介、BV号和页面 URL；结果只是候选资料。
- `bilibili_watch`：接收候选 URL 或 BV号，复用本插件的 yt-dlp 下载、字幕/OCR 和 DSH Video Storyboard 分镜链，把最多4张真实 PNG 分镜作为工具媒体交给主模型。
工具只允许蓝铃已绑定的主人私聊，执行时还会核对身份插件和真实会话；群聊、其他私聊或无法核验身份时拒绝。搜索接口与现有B站下载一样不使用本机代理。只有 `bilibili_watch` 成功返回分镜图时才可描述视频画面；标题、简介或下载失败文本不构成观看证据。

## 本机视频

主人私聊明确给出 Windows 绝对路径并要求观看时，通过 `tool_search` 发现 `watch_local_video`，首次只传 `path`。默认 `mode=auto`：长视频先浏览完整时间轴，短视频和已经指定的时间段沿用精读。也可明确指定 `mode=overview` 或 `mode=detail`。文件直接在本机读取，不上传、复制或先把整部转码。

长视频的默认流程：

1. 读取总时长、章节和已有同名/内嵌文字字幕。
2. 直接跳到分布在全片的采样时刻，最多取得64张独立、带时间索引的JPEG画面，最高1920×1080。没有把原图拼成小格子，也不先对全片做密集OCR。
3. 主模型结合全片画面、已有字幕与用户问题定位关键部分；已有可靠且有用的结论可以先回复，再继续查证。
4. 通过同一工具传 `mode=detail`、`start_seconds`、`end_seconds` 精读所选片段，补充场景分镜和画面文字。明确给出时间点时可以直接精读，不必先做总览。

不要机械地从头串行扫每十分钟，也不要反复获取相同概览。每张概览画面使用原视频时间，失败的采样单独列出，不能拿别的画面充数。全片抽样不等于逐帧看完，未采到也不等于没有发生；需要确认动作、对白或画面文字时继续读取对应片段。无可用字幕或音频转写时，不能声称听过对白。工具仅对真实主人私聊开放，群聊、其他私聊和UNC网络路径均拒绝。

## 处理边界

- 每条消息最多成功读取一个视频，每台机器人同时处理一个任务。消息中的链接按出现顺序尝试；仅在未识别到视频时继续下一链接，访问被拒绝或已识别视频下载失败时保留实际错误。入站只登记来源，解析和下载延后到实际模型请求，所有候选共用一次180秒预算。QQ 本机视频及转发视频通过公开 NapCat API 读取原消息，在核对消息 ID、会话、群 ID 和原发送者后，使用结构化视频段返回的下载地址或绝对文件路径，路径不可读时按原视频文件标识调用 `get_file` 补下载；自动附件入口不从聊天正文读取磁盘文件；主人私聊明确指定的本机路径由下述工具单独核验。转发最多3层、64节点、4次查询和256个消息段，依赖 `api.call` 权限。
- 公网下载仍限制80 MiB、10分钟。网页视频有多档清晰度时选择不超过720像素的可用档位并合并音轨；解析阶段未提供尺寸的媒体仍可下载，再由实际解码核对分辨率和时长。本机文件不套下载大小上限；概览覆盖整个选择范围，精读每次最多10分钟，可按问题选择任意片段继续。解码分辨率上限4000万像素。
- 本机概览直接快进取帧，最多4个取帧进程并行，60秒总预算；每张原图单独交给主模型，读取失败明确标注。本机精读使用DSH的`full`策略和至少4个代表帧；现有公网视频分镜仍使用`compact`策略，最多4张分镜图。
- 单次视频任务总预算180秒。精读的字幕取帧30秒、OCR子进程65秒、DSH子进程110秒；任务取消时结束全部取帧及解码进程，清理临时目录。
- 概览优先读取同名字幕文件或内嵌文字字幕，字幕全文保留；没有现成文字字幕时先看全片画面，不等待密集识字。所选精读片段仍可每0.5秒读取画面文字、合并重复行并给出原视频绝对时间。画面OCR不是音频转写，可能包含片名、水印或错字。
- 分镜原图最多缓存8项、24 MiB、1小时，仅存进程内存。消息映射最多128项，并按真实会话和消息ID隔离。链接解析、下载、分镜或QQ原文件取得失败后，同一原消息120秒内复用失败结果，避免规划、回复和后续请求重复读取；新发送的链接或视频消息可立即重试。每次请求优先处理最新含链接或视频的消息；后续引用时间清单回答追问。
- OCR最多1200帧、55秒识别预算，文字时间表最多32000字符；达到限制时明确标记未完成。临时视频、字幕、采样帧和引擎状态在成功、失败或取消后清理，QQ原有视频缓存保持原样。卸载等待任务和子进程结束。

网页下载遇到临时连接中断时，在既有90秒预算内最多尝试三次。当前请求已附入成功分镜及对应图片时，以本次读取结果为准，先前规划或聊天中的失败状态已过期。

链接未识别到视频、访问被拒绝、下载或分镜失败时，主模型收到带实际原因的 `[视频未读取]`；未识别到视频不表示网页为空或无法访问。没有读取状态表示尚未读取，不能声称已经打开链接；只有附入实际分镜后才可描述画面，不根据标题或其他图片编造内容。日志记录附给模型的图片数、格数、时长和工具错误；下载 URL 在工具诊断中脱敏。来源和许可证见 [vendor/NOTICE.md](vendor/NOTICE.md)。
